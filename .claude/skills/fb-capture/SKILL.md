# fb-capture

## 목적
- 작업 중 발생하는 즉각적인 피드백을 손실 없이 수집한다.
- `--project` 여부에 따라 프로젝트별 또는 전역 저장소에 기록한다.
- 나중에 `/fb-apply`가 처리할 수 있는 구조화된 형식으로 저장한다.
- 피드백이 규칙/스킬/훅/문서 개선으로 이어지는 순환 고리를 형성한다.

## 호출 방식

| 호출 | 동작 |
|---|---|
| `/fb --project {내용}` | 현재 프로젝트 피드백으로 저장 |
| `/fb {내용}` | 전역/프로젝트 여부를 물어본 후 저장 |
| `/fb flush` | 현재 대화에서 오간 피드백을 일괄 정리 후 범위 질문 후 저장 |

- ⚠️ `/feedback`은 Claude Code 내장 버그 리포트 명령어 — 절대 사용하지 않는다

## 저장 경로

| 범위 | 저장 경로 |
|---|---|
| `--project` 명시 | `{프로젝트 루트}/docs/feedback/YYYY-MM-DD-session.md` |
| 전역 (global) | `~/.claude/docs/feedback/YYYY-MM-DD-session.md` |

디렉터리가 없으면 자동 생성한다.

## 범위 확인 흐름

`--project` 플래그가 없을 경우 반드시 물어본다:
```
이 피드백을 어디에 저장할까요?
[1] 이 프로젝트에만 (docs/feedback/)
[2] 전역 — 모든 프로젝트에 적용 (~/.claude/docs/feedback/)
```

## 저장 형식

파일 헤더 (첫 항목 추가 시):
```markdown
# 세션 피드백 — YYYY-MM-DD

> scope: project | global
> 이 파일은 append-only입니다. `/fb-apply [--project]`로 처리합니다.
```

각 항목:
```markdown
## [HH:MM] 피드백 #N
- **컨텍스트**: {도메인명 또는 피처명}
- **피드백 내용**: {원문 그대로}
- **카테고리**: rule | skill | convention | behavior | other
- **영향 대상**: {예: .claude/skills/fb-capture/SKILL.md, 미정}
- **액션**: 즉시적용 | 검토필요 | 참고만
- **상태**: [ ] 미처리
```

### 카테고리 기준
- `rule`: 행동 방식, 접근 방식, 절차에 관한 피드백
- `skill`: 특정 스킬의 동작/출력에 관한 피드백
- `convention`: 코드 스타일, 네이밍, 포맷에 관한 피드백
- `behavior`: AI의 응답 방식, 말투, 설명 방식에 관한 피드백
- `other`: 위에 해당하지 않는 기타 피드백

## 워크플로우

### `/fb --project {내용}` 실행 시
1. 저장 경로: `{프로젝트 루트}/docs/feedback/YYYY-MM-DD-session.md`
2. 파일이 없으면 헤더(`scope: project`) 포함하여 새로 생성
3. 기존 파일의 마지막 항목 번호 확인 (없으면 #1부터 시작)
4. 피드백 내용에서 카테고리 추론
5. 영향 대상 파일 추론 (확실하지 않으면 "미정" 기재)
6. 항목 append
7. 저장 완료 알림: `✓ fb #N 저장됨 (카테고리: {카테고리}, 위치: project)`

### `/fb {내용}` 실행 시 (플래그 없음)
1. 범위 질문:
   ```
   이 피드백을 어디에 저장할까요?
   [1] 이 프로젝트에만 (docs/feedback/)
   [2] 전역 — 모든 프로젝트에 적용 (~/.claude/docs/feedback/)
   ```
2. 선택에 따라 경로 결정 후 위와 동일하게 처리

### `/fb flush` 실행 시
1. 현재 대화에서 피드백으로 볼 수 있는 발언 목록 추출
2. 각 항목을 위 형식으로 정리하여 사용자에게 보여줌
3. 범위(project/global) 질문
4. 사용자 확인 후 일괄 append

## 게이트
- 피드백 내용이 비어 있지 않다.

## 중단 조건
- 피드백 내용이 없다 → "어떤 피드백을 저장할까요?"

## 차단 시 반환 형식
- 현재 stage: `fb-capture`
- 차단 사유: 내용 없음
- 다음 필요 입력: 피드백 내용
