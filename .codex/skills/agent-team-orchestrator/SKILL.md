# 개발 에이전트 팀 오케스트레이션

**실행 모드:** 에이전트 팀. 호출하는 모든 역할은 `model: opus`를 사용한다.

호출 전 `.agents/agent-team.md`를 읽어 Claude와 공유하는 역할·권한·협업 기준을 적용한다.

## 역할

- `backend-planner`: 읽기 전용 작업 분해와 계약 확인
- `backend-developer`: 코드와 집중 테스트 수정
- `backend-reviewer`: 읽기 전용 명세·품질 독립 검토
- `backend-orchestrator`: 작업 배정·상태·결과 통합

## 워크플로우

1. 기존 산출물과 사용자 요청을 확인한다. 부분 수정이면 영향을 받은 역할만 다시 호출한다.
2. `backend-planner`로 변경 범위와 작업 계약을 확인한다.
3. 필요한 `backend-developer`만 호출한다. 독립적인 작업만 병렬로 실행한다.
4. `backend-reviewer`가 명세·품질을 판정한다. 발견 사항은 심각도와 근거를 포함해야 한다.
5. 실행 가능한 발견만 해당 개발자에게 전달해 최소 수정 후 관련 검증을 재실행한다.
6. 변경, 검증, 미해결 항목을 사용자에게 보고한다.

## 통신과 실패 처리

- 작업 상태는 태스크로, 짧은 확인은 메시지로 전달한다.
- 결과가 길거나 감사가 필요하면 `_workspace/{phase}_{agent}_{artifact}.md`에 저장한다.
- 역할이 실패하면 한 번 재시도한다. 재실패하면 누락을 보고하고 독립 작업은 계속한다.
- 리뷰 결과가 없으면 승인으로 간주하지 않는다.

## 테스트 시나리오

- 정상: API와 화면 변경 요청 → 탐색 → 백엔드·프론트 구현 병렬 → 두 리뷰 병렬 → 필요한 최소 수정과 검증.
- 오류: 리뷰어가 재시도 후에도 실패 → 구현 검증은 완료하되, 리뷰 미실행 사실을 결과에 명시.
